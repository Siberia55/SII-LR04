# Лабораторная работа № 4. Подсчёт объектов в видео

**Вариант:** 20  
**Класс объектов:** `handbag` (сумки)  
**Шаг обработки:** 15 кадров  
**Модель:** YOLO26n (`yolo26n.pt`)

## Описание

Программа обнаруживает сумки на видео с помощью YOLO и OpenCV, подсчитывает обнаружения на обработанных кадрах, сохраняет кадры с рамками и формирует JSON-отчёт.

## Возможности

- Обработка видеофайлов.
- Выбор класса объектов и шага обработки кадров.
- Подсчёт среднего и максимального количества обнаружений.
- Сохранение обработанных кадров с рамками.
- Формирование `report.json`.
- Измерение времени выполнения.
- Указание ограничений при отсутствии трекера.

## Структура проекта

- `src/count_video.py` — основной код.
- `data/` — входные видео.
- `output/` — отчёты и обработанные кадры.
- `models/` — каталог моделей.
- `Dockerfile` — сборка образа.
- `compose.yaml` — конфигурация Docker Compose.
- `requirements.txt` — зависимости.

## Запуск

Необходимы Docker и Docker Compose.

Сборка:

```bash
docker compose build
```

Проверка параметров:

```bash
docker compose run --rm video-counter python -m src.count_video --help
```

Обработка видео:

```bash
docker compose run --rm video-counter \
  python -m src.count_video \
  --source data/sample.mp4 \
  --class handbag \
  --stride 15
```

Обработка второго видео с отдельным каталогом результатов:

```bash
docker compose run --rm video-counter \
  python -m src.count_video \
  --source data/sample2.mp4 \
  --class handbag \
  --stride 15 \
  --output output/sample2
```

## Параметры

- `--source` — путь к входному видео.
- `--class` — класс объектов.
- `--stride` — шаг обработки кадров, по умолчанию `15`.
- `--model` — модель YOLO, по умолчанию `yolo26n.pt`.
- `--output` — каталог результатов, по умолчанию `output`.
- `--conf` — порог уверенности детекции, по умолчанию `0.25`.

## Результаты

В каталоге результатов создаются `report.json` и папка `frames/` с кадрами, на которых нарисованы рамки обнаруженных объектов.

В отчёте указываются общее количество кадров, число обработанных и пропущенных кадров, среднее и максимальное число обнаружений, время выполнения и сведения о трекере.

## Влияние stride

При `stride = 15` обрабатывается каждый пятнадцатый кадр, начиная с индекса 0. Это сокращает число запусков модели и время обработки, но объекты и события между выбранными кадрами могут быть пропущены.

## Ограничения

Трекер не используется. Программа не связывает обнаружения одного объекта между кадрами, поэтому количество обнаружений не равно количеству уникальных сумок за всё видео. В отчёте `unique_tracks` имеет значение `null`, а `tracker_used` — `false`.
